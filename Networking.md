# Networking

## Configure networking and hostname resolution statically or dynamically

* `ip addr show`

  Show IP addresses configuration

  * `ip a s` 

    Short syntax

  * `ip -c addr show`

    Show IP addresses configuration with colored output

* `nmtui`

  *Network Manager Text User Interface* - Graphical interface to manage network connections configuration

  * Manual means that IP will be configured manually
  * Automatic means that will be used DHCP protocol
  * **NOTE**: IP must be inserted with syntax IP/NETMASK (e.t. 192.168.0.2/24)

* Netplan (Ubuntu and similar systems)

  * Netplan configuration files are stored in `/etc/netplan/*.yaml`.

  * DHCP example (`enp0s3`):

  ```yaml
  network:
    version: 2
    ethernets:
      enp0s3:
        dhcp4: true
  ```

  * Static IPv4 example:

  ```yaml
  network:
    version: 2
    ethernets:
      enp0s3:
        dhcp4: false
        addresses:
          - 192.168.0.10/24
        routes:
          - to: default
            via: 192.168.0.1
        nameservers:
          addresses:
            - 1.1.1.1
            - 8.8.8.8
  ```

  * Apply changes with `sudo netplan try`, `sudo netplan apply`, and optionally `sudo netplan generate`. `netplan try` is safer for remote systems because it temporarily applies changes and automatica[...]

  * YAML is indentation-sensitive (spaces, not tabs). If configuration files include sensitive information, restrict permissions (for example with `sudo chmod 600 /etc/netplan/*.yaml`).


* All network configuration will be stored in `/etc/sysconfig/network-scripts`

* If there is need to change IP configuration of an interface without using `nmtui` remember to shutdown interface, change IP, restart interface
  * `ip link set eth0 down` Shutdown interface eth0
  * `ip addr add 192.168.0.2/24 dev eth0` Assign IP 192.168.0.2/24 to interface eth0
  * `ip link set eth0 up` Restart interface eth0



* The hostname can be changed editing `/etc/hostname`

  * `hostname` show current hostname
  * Alternative: `hostnamectl set-hostname your-new-hostname` set hostname equal to your-new-hostname
  * Reboot is required to see new hostname applied

* In `/etc/hosts` is configured a name resolution that take precedence of DNS 

  * It contains static DNS entry

  * It is possible add hostname to row for 127.0.0.1 resolution, or insert a static IP configured on principal interface equal to hostname

*  In `/etc/resolv.conf` there are configured DNS servers entry

  * It is possible to insert more than one *nameserver* as backup (primary and secondary)

## Implement packet filtering

### Netfilter fundamentals

* Linux firewalling is provided by the kernel's **Netfilter** framework.
* Netfilter evaluates packets through chains such as:
  * **INPUT** — packets entering the local system
  * **OUTPUT** — packets generated by the local system
  * **FORWARD** — packets routed through the system
  * **PREROUTING** and **POSTROUTING** — packet processing before and after routing decisions
* Rules in a chain are evaluated in order.
  * The first matching rule is applied and later rules are skipped.
  * If no rule matches, the chain's default policy is applied.
* Common policies:
  * **ACCEPT** — allow the packet to continue.
  * **DROP** — silently discard the packet.
  * **REJECT** — discard the packet and notify the sender, usually with an error response.

### UFW

* **UFW** (*Uncomplicated Firewall*) is the standard command-line firewall tool on Ubuntu.
* UFW provides a simpler interface for managing Netfilter rules.

#### Default policies

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
```

* Deny unsolicited incoming connections by default.
* Allow outgoing connections by default.
* Configure required allow rules before enabling UFW, especially when connected through SSH.

#### Check firewall status

```bash
sudo ufw status verbose
sudo ufw status numbered
```

* `status verbose` displays the current state, default policies, and active rules.
* `status numbered` displays rules with numbers, which can be used to delete individual rules.

#### Enable, disable, and reset UFW

```bash
sudo ufw enable
sudo ufw disable
sudo ufw reset
```

* `ufw enable` enables the firewall and starts applying its rules.
* `ufw disable` stops enforcing UFW rules.
* `ufw reset` removes all rules and restores UFW to its initial disabled state.
* Use `ufw reset` carefully because it removes existing firewall configuration.

#### Allow and deny ports

```bash
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 53/udp
sudo ufw deny 23/tcp
sudo ufw delete deny 23/tcp
```

* `allow` permits traffic.
* `deny` blocks traffic.
* Specify the protocol with `/tcp` or `/udp` when required.
* Rules can also use port ranges:

```bash
sudo ufw allow 4000:4005/tcp
```

#### Allow or block specific subnets

```bash
sudo ufw allow from 192.168.1.0/24
sudo ufw allow from 192.168.1.0/24 to any port 22 proto tcp
sudo ufw deny from 203.0.113.0/24
```

* Rules can allow or deny all traffic from a source subnet.
* Rules can also restrict the source subnet to a specific destination port and protocol.

#### Restrict rules to a network interface

```bash
sudo ufw allow in on eth0 to any port 22 proto tcp
sudo ufw deny in on eth1 to any port 80 proto tcp
```

* `in on <interface>` applies the rule to traffic arriving through a specific interface.
* Replace `eth0` or `eth1` with the actual interface name shown by `ip addr`.

#### Delete rules by number

```bash
sudo ufw status numbered
sudo ufw delete 3
```

* List the rules first with `ufw status numbered`.
* `ufw delete <number>` removes the rule with the specified number.
* Rule numbers can change after a rule is deleted, so check the list again before deleting another rule.

#### Application profiles

```bash
sudo ufw app list
sudo ufw app info "Nginx Full"
sudo ufw allow 'Nginx Full'
```

* Application profiles define the ports required by common applications.
* `ufw app list` displays available profiles.
* `ufw app info "<profile>"` displays the ports and protocols in a profile.
* `ufw allow 'Nginx Full'` allows HTTP and HTTPS traffic for the Nginx application profile.

### nftables fallback

* `nft list ruleset` — display the complete active nftables ruleset.
* `nft list tables` — list the nftables tables currently configured.
* `nft list chain inet filter input` — display the rules in the input chain.
* `nft flush ruleset` — remove the complete active ruleset; use with caution.
* UFW may manage the underlying Netfilter rules, so avoid mixing manual nftables changes with UFW unless you understand the interaction.

## Start, stop, and check the status of network services

* Network services are controlled as other daemon with `systemctl` command
  * `systemctl status servicename`

* `ss` is used to inspect sockets and listening network services
  * `ss -tunlp`
    * Show listening TCP and UDP ports, including the processes using each socket, without resolving service names
    * `-t` TCP sockets
    * `-u` UDP sockets
    * `-n` show numerical addresses and port numbers
    * `-l` listening sockets
    * `-p` show process information; may require `sudo`
  * `ss -tan`
    * Show all TCP connections, including established connections
  * `ss -s`
    * Show socket usage statistics

* With `netstat` is it possible list internet port opened by a process
  * `yum -y install net-tools`
  * `netstat -tln`
    * Show TCP port opened by processes



## Statically route IP traffic

* `ip route show`
  * Print route
  * Alternative command `route -n`
* `ip route add 192.0.2.1 via 10.0.0.1 [dev interface]`
  * Add route to 192.0.2.1 through 10.0.0.1. Optionally interface can be specified
* To make route persistent, create a *route-ifname* file for the interface through which the subnet is accessed, e.g eth0:
  * `vi /etc/sysconfig/network-scripts/route-eth0`
  * Add line `192.0.2.1 via 10.0.0.101 dev eth0`
  * `service network restart` to reload file

* `ip route add 192.0.2.0/24 via 10.0.0.1 [dev ifname]` 
  * Add a route to subnet 192.0.2.0/24



* To configure system as route forward must be enabled
  * `echo 1 > /proc/sys/net/ipv4/ip_forward`
  * To make configuration persistent
    * `echo net.ipv4.ip_forward = 1 > /etc/sysctl.d/ipv4.conf`

## Synchronize time using other network peers

* In time synchronization the concept of Stratum define the accuracy of server time.
* A server with Stratum 0 it is the most reliable
* A server synchronized with a Stratum 0 become Stratum 1
* Stratum 10 is reserved for local clock. This means that it is not utilizable
* The upper limit for Stratum is 15
* Stratum 16 is used to indicate that a device is unsynchronized
* Remember that time synchronization between servers is a slowly process



CHRONYD

* Default mechanism to synchronize time in CentOS
* Configuration file `/etc/chrony.conf`
* `server` parameters are servers that are used as source of synchronization
* `chronyc sources` contact server and show them status
* `chronyc tracking` show current status of system clock

  * Simple solution: `setenforce 0`
  * Package `selinux-policy-3.13.1-229` should resolve problem



NTP

* The old method of synchronization. To enable it Chronyd must be disabled
* Configuration file `/etc/ntp.conf`
* `server` parameters are servers that are used as source of synchronization
* `ntpq -p` check current status of synchronization
